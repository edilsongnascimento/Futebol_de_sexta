FUTEBOL DE SEXTA — arquivos para Acode
=====================================

O QUE VEM NESTA PASTA
- index.html: tela principal
- style.css: visual para celular
- app.js: confirmações e convidados
- config.js: conexão com Supabase (preencher)
- supabase.sql: estrutura inicial do banco e regras RPC
- manifest.json, icon.svg, sw.js: instalação PWA
- Este arquivo: instruções

IMPORTANTE
Esta é a primeira versão funcional de interface + base de dados. Ela ainda NÃO está pronta para uso público até você configurar o Supabase, criar os sócios e publicar um jogo. A área administrativa dentro do app ainda não está implementada; cadastros iniciais são feitos no painel Supabase. Não coloque uma chave service_role no site.

PASSO 1 — COPIAR PARA O ACODE
1. Baixe e extraia o ZIP.
2. No Acode, abra a pasta futebol_de_sexta_acode.
3. Confira se index.html, style.css, app.js, config.js, manifest.json, icon.svg e sw.js estão na mesma pasta.

PASSO 2 — CRIAR O SUPABASE
1. Entre em https://supabase.com e crie um projeto.
2. Abra SQL Editor > New query.
3. Abra o arquivo supabase.sql, copie tudo e cole no SQL Editor.
4. Execute. Se aparecer erro, pare e envie a mensagem para correção.

PASSO 3 — CONFIGURAR A CONEXÃO
1. No Supabase, abra Project Settings > API (ou Connect, dependendo da interface).
2. Copie a Project URL.
3. Copie a chave publicável (publishable/anon). NÃO copie service_role/secret.
4. Abra config.js no Acode e substitua:

PASSO 4 — CADASTRAR SÓCIOS E LINKS
A geração de links individuais e códigos ainda precisa ser feita por uma rotina administrativa segura. Não invente tokens manualmente nem compartilhe links entre sócios. Antes de colocar o app em uso real, precisamos criar a tela administrativa que gera tokens fortes e códigos de ativação, cadastra sócios, publica jogos, registra presença real e permite reabrir jogos.

PASSO 5 — PUBLICAR
Para instalar como aplicativo, publique os arquivos em um endereço HTTPS, por exemplo GitHub Pages. PWA e service worker não funcionam corretamente abrindo o arquivo direto como file://.
Depois de publicar, cada sócio receberá o próprio link, por exemplo:
https://SEU-USUARIO.github.io/SEU-REPOSITORIO/?socio=TOKEN_INDIVIDUAL
O exemplo acima é ilustrativo; não use o mesmo token para todos.

LIMITES DESTA VERSÃO
- Capacidade inicial configurada em 18 pessoas no total (14 linha + 2 goleiros + 2 reservas).
- O banco de dados bloqueia confirmação e convite quando o jogo está fechado ou chega a 18 participantes.
- Esta versão não monta automaticamente os dois times nem inclui a área administrativa completa.
- A ativação por código está preparada na interface e SQL, mas o fluxo de criação e entrega dos códigos depende da futura tela administrativa.
- A instalação PWA não autentica a pessoa por hardware. Link individual é um segredo: quem o recebe pode tentar usá-lo; por isso não o encaminhe em grupos.
- Antes de usar com todos, recomendo testar com 2 sócios fictícios e um jogo de teste.

PRÓXIMA ETAPA RECOMENDADA
Implementar a área administrativa segura com login de administrador, cadastro de sócios, geração de links e códigos, criação automática das próximas sextas, regras editáveis, lista de presença real e divisão dos times.
